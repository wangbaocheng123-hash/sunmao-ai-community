# ADR-0002：采用第一方匿名访问统计与独立管理后台

- 状态：已接受，待所有者发布授权后上线
- 日期：2026-10-13

## 背景

社区需要让所有者看到访问量、最近访客、访问页面、来源与设备，并为后续内容管理、账号、收费和广告建立统一后台。当前系统是 Python 标准库 HTTP 服务与单个 SQLite 数据库，没有账号或第三方分析服务。

“有哪些人访问”在没有会员账号的阶段不能等同于真实姓名。直接保留 IP 或服务器原始访问日志会增加隐私和数据安全负担，也不能可靠代表一个真实的人。

## 决策

1. 在现有服务内增加 `/admin/` 管理入口，继续保持模块化单体，不引入第二套后台服务。
2. 浏览器使用第一方随机访客 Cookie 与 30 分钟访问会话 Cookie；数据库只保存随机值的 SHA-256 摘要和“木友-XXXXXX”编号。
3. 不保存 IP 地址、完整 User-Agent 或来源页面路径，只保留来源域名、设备类别、访问栏目和聚合数据。
4. 管理员密码只保存 PBKDF2-SHA256 摘要，默认读取 `/var/lib/sunmao-community/admin-password.hash`；摘要文件属于运行数据，不进入 Git。
5. 管理员登录会话保存在进程内存，最长 12 小时；社区服务重启后需要重新登录。
6. 统计明细保留 365 天，累计计数继续保留。以后会员登录后，可在取得必要告知与授权的前提下把匿名访问与会员账号关联。

## 安全边界

- 所有写入接口继续要求同源请求。
- 后台统计接口必须通过管理员会话认证。
- 后台页面禁止搜索引擎索引，认证 Cookie 使用 `HttpOnly`、`SameSite=Strict`，HTTPS 下同时使用 `Secure`。
- 统计失败不影响公开社区的留言与浏览。
- 本次变化只使用社区自己的进程和数据库，不读取或修改北京博主采集器。

## 被否决的方案

- **直接接入第三方统计脚本**：会把访客数据交给外部平台，增加 Cookie、合规和脚本供应链成本。
- **用 Caddy 原始日志统计**：容易保留 IP，且难以稳定识别同一匿名访客与社区内栏目切换。
- **先建设完整会员系统再统计**：交付周期过长，不能先回答最基本的经营问题。
- **拆分微服务**：当前体量没有收益，会增加部署、监控和故障边界。

## 后续演进

后台继续沿同一入口增加内容审核、资料管理、会员和订单模块。SQLite 适合当前小规模；当持续写入并发、数据量或报表查询成为明确瓶颈时，再通过 ADR 评估迁移 PostgreSQL，而不是预先复杂化。
