# ADR-0005：固定主理人身份与 30 天免登录

- 状态：已实现并本地验证，开发版本 `0.3.3`，未发布
- 替代 ADR-0002 第 5 条的内存会话策略

## 决策

1. 唯一管理员使用固定内部身份 `owner`、显示名“主理人”。身份以密码认证为依据，不以 IP、网络、昵称或客户端提交的身份字段为依据。电脑和手机分别认证后属于同一身份。
2. 默认勾选“此设备保持登录 30 天”。凭证为密码验证后随机生成的 32 字节 token；浏览器 Cookie 使用 HttpOnly、SameSite=Strict，并在 HTTPS 下使用 Secure；不在浏览器保存密码。服务器仅把 token 摘要、密码配置指纹、绝对到期时间及记住选项保存在社区原 SQLite 数据库。正常发布、服务重启保留会话；访问不会延长绝对期限。
3. 不勾选记住时使用无 Max-Age 的浏览器会话 Cookie，服务器最长期限为 12 小时。主动退出删除服务器凭证，同时清除该浏览器的登录和访客 Cookie，以免退出后使用同一浏览器的人沿用主理人统计编号。其他已登录设备不受影响。
4. 密码摘要配置改变并重启服务后清除旧指纹凭证；到期凭证也会清理。管理员密码和存储路径沿用原配置。本次不提供新账号注册或密码修改界面。
5. 密码登录、已认证的自动登录恢复、已认证浏览事件，均可将当前浏览器的访客摘要与主理人关联。该映射只用于统计，不能授予后台权限；过期或退出后仍须验证有效凭证才能访问后台。未能确认的旧匿名编号不合并，也不按相同 IP 推断身份。
6. 最近访客、累计/当日访客、在线人数将主理人的已验证设备合并为一个身份；访问次数和浏览次数仍按实际行为累计。匿名访客继续按原随机浏览器编号计数。后台可切换“排除主理人”。
7. 为准确过滤趋势、页面、来源和设备，新建逐浏览器的每日贡献聚合。既有访客累计和每日独立访客能通过已确认映射识别；升级前不存在的逐浏览器分项明细不能推测还原，旧分项保留原口径并在启用过滤时明确提示。无需清空或重建历史业务表。新的细分聚合沿用 365 天保留策略；主理人的累计贡献保持累计，以免明细清理导致累计口径变化。
8. 后台另列最近 50 条成功登录记录，包含固定身份、时间、设备类别、密码/自动登录方式。每次进入后台触发一次恢复记录；后台统计轮询不重复记为登录。记录最多保留 365 天，不保存 IP、完整 User-Agent、密码或原始会话 token。新接口需要后台认证；恢复接口还需要同源 POST。
9. 同源校验补充所有者确认的 `amuyeye.com` / `www.amuyeye.com` HTTPS 来源；保留旧域名兼容。不修改 DNS、反向代理或服务发布配置。不同域名的 Cookie 独立，切换域名需要重新验证。

## 验证与发布边界

- 自动化验证固定到期、重启恢复、密码配置改变失效、登出撤销、网络变化不改变身份、两设备合并、同 IP 匿名访客不提权、Cookie 安全属性、同源约束和历史迁移口径。
- `python -m scripts.verify_owner_ui` 用临时数据和生成密码运行 Chromium，验证桌面、390/360px、浏览器关闭后恢复、服务重启、登录记录、过滤及退出。截图只包含临时测试数据。
- 本次用户指令为执行已确认功能方案；修改并推送 `main`，保持 `production` 不变。待收到发布指令后按社区既有流程发布；不得操作北京博主采集器。
