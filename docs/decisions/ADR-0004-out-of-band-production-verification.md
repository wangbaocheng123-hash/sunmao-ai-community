# ADR-0004：域名故障时的独立生产版本验收

- 状态：已接受
- 日期：2026-10-14

## 背景

`阿木爷爷.com` 指向北京阿里云服务器。北京服务器自身访问 HTTPS 正常，但 Codex Cloud、GitHub Actions 和桌面外部网络实测会收到阿里云 `Non-compliance ICP Filing` 403 或 TLS 握手失败。`0.3.2` 实际已经由 Webhook 自动部署成功，云端却因为无法读取域名而把发布误报为失败。

部署状态与域名合规/可访问性是两个不同事实，必须分别验证和报告。不能为了验收给云端环境配置北京 SSH，也不能新增 Git 轮询。

## 决策

1. 北京 Caddy 在服务器公网 IP 的 HTTP 虚拟主机上只开放 `GET`、`HEAD /health/version`，反向代理到社区回环端口；其他路径一律404。
2. 该响应只包含服务名、版本、部署时间和公开的 Git 提交号，不包含凭据、用户数据、后台数据或写能力，并设置 `no-store`。
3. 发布脚本先尝试正式 HTTPS 域名；域名不可达时使用只读 IP 探针核对精确 `production` 提交。GitHub Actions 使用同一探针，只负责验证，不能发布。
4. 正式用户入口仍是 `https://阿木爷爷.com/`。IP 探针不是网站备用入口，不能掩盖备案问题；域名恢复需另行完成备案或经所有者确认迁移境外入口。
5. 不增加定时器、常驻代理、服务器密钥或对新加坡运行时的依赖。北京博主采集器与模型下载器不受影响。

## 后果

- 手机 Codex 可以准确区分“北京未部署”和“域名被备案边缘阻断”，不再因域名故障否定已成功的发布。
- 探针使用明文 HTTP，只适合核对无敏感信息的公开提交号；它不能证明正式域名的 TLS 或用户页面可访问。正式域名状态必须单独报告。
