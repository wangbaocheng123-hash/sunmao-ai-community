# 榫卯 AI 社区后台与商业化框架

## 产品原则

社区保持“小而美”：一个公开网站、一个管理后台、一个清晰的会员体系。先验证木友真正需要的内容和服务，再增加收费与广告；不做与社区无关的通用大平台。

技术上继续采用模块化单体。访问统计、内容、交流、会员、订单和广告在代码中分模块，在部署上仍是 `sunmao-ai-community.service`，共用社区自己的数据库与备份流程。这样成本低、维护路径短，也不会触碰同机的北京博主采集器。

## 后台信息架构

| 后台模块 | 主要能力 | 当前状态 |
| --- | --- | --- |
| 数据中心 | 今日/累计访问、匿名访客、页面、来源、设备 | 第一版已完成 |
| 内容中心 | 榫卯 108 道、尺寸资料、文章、附件、上下架 | 下一阶段 |
| 交流管理 | 留言审核、隐藏、回复、举报、敏感操作记录 | 下一阶段 |
| 用户中心 | 账号、角色、状态、会员等级、用户资料 | 账号阶段 |
| 会员与订单 | 商品、权益、订单、支付、退款、到期时间 | 商业化阶段 |
| 广告与合作 | 广告位、素材、起止时间、展示/点击、合作方 | 商业化阶段 |
| 系统设置 | 管理员、权限、审计日志、备份与运行状态 | 随后台演进 |

后台角色建议只保留四类：所有者、内容编辑、社区管理员、客服。每项敏感操作记录“谁、何时、改了什么”，支付和退款必须单独授权。

## 分阶段落地

### 第一阶段：先看清社区使用情况

- 已实现 `/admin/` 密码登录。
- 已实现匿名访客、访问会话、页面浏览量、来源域名、设备类型与趋势。
- 统计从功能正式上线后开始，不从服务器旧日志反推历史访客。
- 当前“访客”是浏览器匿名编号，不代表真实姓名；上线账号系统后才可显示已登录会员。

### 第二阶段：先把交流和资料管好

- 留言列表、搜索、隐藏、恢复、回复和举报处理。
- 榫卯视频、尺寸资料、分类、标签、封面与上下架时间。
- 图片或图纸放对象存储，SQLite 只保存元数据和地址。
- 内容变更保留审计记录，公开区继续默认纯文字并限制频率。

### 第三阶段：建立轻会员体系

- 手机号或微信登录，先选择一种主登录方式，避免并行维护多套身份。
- 角色与权益独立：免费会员、付费会员、单项资料购买。
- 交流增加回复、收藏、关注和通知；私信等高审核成本功能不优先。
- 匿名访客只有在登录并完成必要告知后才关联会员账号。

### 第四阶段：收费

推荐先卖明确价值，不先做复杂订阅：

1. 免费层：公开交流、部分榫卯视频索引、少量尺寸资料。
2. 单项购买：一套图纸、一个尺寸包或一个专题课程，价格和交付边界清楚。
3. 会员层：资料库访问、AI 问答额度、课程折扣或优先答疑；需求稳定后再做月/年费。

订单模型应分开保存“商品、订单、支付记录、权益、退款”，不能只给用户表加一个“已付费”字段。支付回调必须验签并具备幂等处理，同一回调重复到达不能重复开通权益。面向中国用户优先评估微信支付和支付宝，接入前准备适合主体的商户账号、服务协议、隐私政策、退款规则和发票流程。

### 第五阶段：广告与品牌合作

初期建议只做少量固定合作位，不接侵入式广告联盟：

- 首页或资料页每页最多一个明确标注“广告/合作”的位置。
- 后台配置合作方、素材、链接、投放时间、展示量和点击量。
- 广告素材与普通内容分表、分权限、分统计，过期自动下架。
- 不基于敏感个人信息定向；不使用伪装成社区内容的广告样式。
- 优先木工工具、材料、课程和展会等与社区高度相关的合作，保持社区质感。

## 数据与技术演进

当前 SQLite 足以支撑早期社区。出现以下任一情况再评估 PostgreSQL：持续写入锁明显影响请求、日活达到数千且互动频繁、需要多进程写入，或后台复杂报表明显变慢。图片、PDF 和图纸不放进数据库，使用独立对象存储并做访问权限控制。

建议逐步建立以下核心实体：

- `users`、`roles`、`user_roles`：账号与权限。
- `content_items`、`assets`、`categories`：内容和资料。
- `threads`、`replies`、`reports`：交流与审核。
- `products`、`orders`、`payments`、`entitlements`、`refunds`：收费与权益。
- `ad_slots`、`campaigns`、`ad_events`：广告。
- `audit_logs`：后台敏感操作。

## 运营与合规底线

- 在收集手机号、支付信息或把匿名数据关联账号前，先完善隐私政策和用户协议。
- 收费内容写清楚交付内容、有效期、退款条件和客服入口。
- 用户交流必须提供举报与处置流程；管理员能隐藏内容并保留必要审计记录。
- 广告必须显著标识，并审核广告主、落地页和宣传用语。
- 数据库、上传资料和支付配置分别备份；密钥、商户证书和生产数据库永不进入 Git。

这套顺序的核心是：先看数据，再管内容，再做身份，最后收费和广告。每一步都能独立产生价值，也不会让早期社区背上过重维护成本。
